# 第一阶段：个人账号与知识库基础设计

## 背景

项目已经具备知识库、文档上传与解析、混合检索、学习对话、知识点、卡片、练习、学习活动、目标和报告等能力。前端已经统一使用“知识库”文案，但后端仍以 `Workspace`、`workspaces` 和 `/api/workspaces` 作为核心兼容契约。

项目也已有可选的单用户密码解锁功能、`UserProfile` 学习偏好以及文档和知识点的 JSON 标签，但当前登录逻辑只读取第一条个人资料，令牌只验证签名和有效期，没有把当前用户注入业务请求。业务查询没有所有者条件，客户端和服务内部仍存在可传入 `user_id` 的路径，因此尚未形成真正的数据隔离。

本阶段在不重做现有功能界面的前提下，建立单账号部署、按多用户结构实现的账号和数据所有权基础；扩展知识库、学习领域、封面和标签编辑能力；使用 Alembic 接管数据库版本迁移，并确保已有知识库、文档、对话和学习记录完整保留。

## 目标

1. 支持首次创建唯一个人账号、登录、退出和恢复登录状态。
2. 支持修改昵称、头像和现有学习偏好。
3. 后端只从认证状态识别用户，不信任客户端传入的 `user_id`。
4. 用户只能访问自己的知识库、文档、知识点、卡片、对话、测验和学习记录。
5. 保留内部 Workspace 兼容契约，用户界面继续统一显示“知识库”。
6. 支持知识库名称、简介、封面、学习目标、学习状态、领域、统计进度和最近学习时间。
7. 支持用户管理学习领域，并支持文档和知识点的多标签人工编辑。
8. 引入 Alembic，保证全新安装和旧数据库升级都有明确、可测试的迁移路径。
9. 保持现有文档上传、解析、检索、学习对话和飞书问答可用。

## 非目标

- 第一阶段不开放公开注册、邀请、切换账号、管理员后台或账号列表。
- 不重做首页、侧边栏、知识库、文档、学习、复习、练习和报告页面的布局与视觉风格。
- 不把内部 `Workspace` 类、`workspaces` 表及 `/api/workspaces` 路径整体重命名。
- 不建立全局标签词典、标签层级、标签订阅或跨用户标签共享。
- 不引入对象存储；头像与封面先保存到受控的本地上传目录，但数据契约允许以后切换存储实现。
- 不在本阶段迁移或重命名 Chroma 集合。
- 不承诺把升级后产生的新账号数据无损降级到旧数据库结构。

## 核心决策

### 单账号部署，多用户数据结构

应用只允许首次创建一个账号。创建成功后关闭设置入口，后续只能登录和退出。数据库、认证依赖、唯一约束和业务查询全部按多用户结构实现，以便未来开放多账号时不重写所有权边界。

`users` 保存认证与公开资料，`learning_preferences` 保存一对一学习偏好。当前 `UserProfile` 的字段和数据迁移到这两个职责明确的实体中。密码继续使用带随机盐的强哈希，不保存或返回明文密码。

用户模型包含：

- `id`
- `username`：同一部署内唯一；第一阶段首次建号时填写，后续登录使用。
- `password_hash`
- `display_name`
- `avatar_kind`：`upload | url | none`
- `avatar_value`：受控相对路径或外部 URL
- `is_active`
- `created_at`, `updated_at`

学习偏好模型包含：

- `user_id`：主键并外键到 `users.id`
- `daily_goal_minutes`
- `daily_review_target`
- `weekly_goal_days`
- `timezone_name`
- `preferred_mode`
- `reminder_time`
- `created_at`, `updated_at`

### 保留 Workspace 兼容

数据库继续使用 `workspaces` 表，后端继续保留 `Workspace` ORM 类型和 `/api/workspaces` 路径。前端类型可以继续叫 `Workspace`，但所有用户可见文案保持“知识库”。这避免同时修改文档上传、向量集合、检索、学习会话、复习、练习、报告和飞书机器人中的大量稳定关联。

`Workspace` 在本阶段是知识库的内部兼容表示，不代表用户界面会新增“工作区”概念，也不要求修改现有导航或页面布局。

### 所有权是服务端约束

认证令牌的 `sub` 保存用户 ID。令牌通过签名和有效期校验后，认证依赖必须从数据库加载有效用户，并把该用户作为 `current_user` 注入路由。仅校验令牌真假而不加载用户不再足够。

所有知识库查询包含 `Workspace.owner_id == current_user.id`。文档、知识点、卡片、对话、测验和学习记录必须通过直接 `user_id` 或所属知识库验证所有权。客户端提交的 `user_id` 被从新请求模型中移除；为兼容旧客户端而暂时保留的字段也必须被忽略，服务端使用当前用户 ID 覆盖。

不存在和不属于当前用户的数据统一返回 404，避免泄露记录是否存在。测试中即使产品界面不能创建第二个用户，也必须直接构造第二个用户验证隔离。

### 服务身份绑定唯一账号

飞书机器人继续使用 `X-KnowBase-Service-Token`，但服务令牌不再意味着不受范围限制。服务身份必须解析为配置的用户；单账号部署默认绑定唯一用户。若数据库中没有可绑定用户，涉及私人数据的飞书请求返回明确错误，不能退化为全库查询。

## 数据模型

### LearningDomain

学习领域是用户拥有的独立实体：

- `id`
- `user_id`
- `name`
- `description`
- `color`
- `created_at`, `updated_at`

同一用户内领域名称唯一，不同用户可使用相同名称。知识库通过可空 `domain_id` 归属一个领域。无领域时 API 和界面显示“未分类”。删除领域只把所属知识库的 `domain_id` 置空，不删除知识库。

### Workspace 扩展

在现有字段基础上增加：

- `owner_id`：非空外键到 `users.id`，并建立索引。
- `domain_id`：可空外键到 `learning_domains.id`，删除领域时置空。
- `cover_kind`：`upload | url | none`。
- `cover_value`：受控相对路径或外部 URL。
- `learning_status`：`not_started | learning | paused | completed`。

现有 `domain` 字符串字段保留一个兼容版本。新代码以 `domain_id` 为准，响应仍可返回 `domain` 名称给旧前端。稳定运行后的独立迁移再移除旧字段。

知识库 slug 从全局唯一改为同一用户内唯一，即唯一约束为 `(owner_id, slug)`。这保留当前 URL 行为，同时允许未来不同用户创建同名知识库。

### 知识库统计

以下字段由真实数据聚合，不在 `workspaces` 中重复存储：

- `document_count`：知识库文档数。
- `knowledge_point_count`：知识点数。
- `learning_progress`：知识点 `mastery` 的平均值；没有知识点时为 0。
- `last_studied_at`：知识库最近一条有效学习活动发生时间；没有活动时为空。

学习状态由用户手动设置，归档状态保持独立。完成学习不自动归档，归档也不自动标记完成。

### 用户归属字段

直接属于用户而不必依赖知识库的记录增加 `user_id`，至少包括用户级目标、学习活动、学习会话和报告建议。已有 `workspace_id` 的领域记录仍以知识库所有权作为主约束；对高频或脱离知识库查询的表可同时保存 `user_id`，但迁移和服务必须保证两者一致。

对话中的历史 `user_id` 必须迁移为真实用户外键或改为明确的所有者字段，不能继续接受任意字符串作为授权依据。

## 标签设计

文档与知识点继续使用现有 JSON 字符串数组保存多标签，避免为当前需求引入标签主数据和多对多关联表。所有写入统一经过规范化：

- 去除首尾空白。
- 删除空标签。
- 按规范化值去重并保留首次出现顺序。
- 限制单个标签长度和标签总数。
- 拒绝非字符串值。

文档已有标签编辑接口继续使用；知识点补充标签编辑能力。AI 生成标签和用户标签写入同一最终字段，但生成流程必须区分“尚无标签”和“已有人工修改”，不得在重新生成学习内容时无条件覆盖人工标签。

第一阶段不提供独立标签管理页面，只在现有文档和知识点编辑入口中维护标签。

## 头像与知识库封面

头像和知识库封面均支持两种来源：本地上传和外部 URL。API 对客户端统一返回可展示的 URL，并保留来源类型以便编辑。

本地上传规则：

- 只接受明确允许的常见图片 MIME 类型和扩展名。
- 同时检查文件头，不能只信任客户端 MIME 类型。
- 限制文件大小和像素范围，拒绝畸形或超大图片。
- 使用随机文件名，禁止用户输入参与磁盘路径。
- 文件保存在专用头像或封面目录，不与原始学习文档混放。
- 替换或删除时，仅清理确认属于对应记录的旧本地文件；外部 URL 不触发文件删除。
- 删除知识库时清理其本地封面；归档知识库保留封面。

外部 URL 只允许 `https`，保存前限制长度。首版不由后端抓取远程图片，从而避免服务端请求伪造风险。

## API 设计

### 认证与当前用户

- `GET /api/auth/status`：返回是否已配置账号和是否需要首次设置，不返回用户私密信息。
- `POST /api/auth/setup`：仅在没有用户时可用，输入用户名、密码、昵称；创建用户和默认学习偏好并返回会话。
- `POST /api/auth/login`：输入用户名和密码，返回访问令牌及基础用户资料。
- `POST /api/auth/logout`：第一阶段用于统一客户端退出语义；客户端删除令牌。若后续引入服务端会话或撤销表，接口保持不变。
- `GET /api/me`：返回当前用户资料。
- `PATCH /api/me`：修改昵称及头像 URL/清除头像。
- `POST /api/me/avatar`：上传头像。
- `GET /api/me/preferences` 与 `PUT /api/me/preferences`：读取和更新学习偏好。

认证保护默认覆盖私人 `/api` 路由，只有健康检查、认证状态、首次设置和登录公开。是否启用认证不再允许生产部署静默关闭数据隔离；开发测试如需绕过，必须使用明确的测试依赖覆盖。

### 学习领域

- `GET /api/learning-domains`
- `POST /api/learning-domains`
- `PATCH /api/learning-domains/{domain_id}`
- `DELETE /api/learning-domains/{domain_id}`

所有操作均从当前用户确定范围。跨用户 ID 返回 404。

### 知识库

保留现有 `/api/workspaces` CRUD。创建和更新请求增加：

- `learning_goal`
- `learning_status`
- `domain_id`
- `cover_url` 或清除封面的显式操作

新增 `POST /api/workspaces/{workspace_id}/cover` 上传本地封面，以及删除封面的接口。列表和详情响应增加领域对象或兼容名称、封面 URL、知识点数、学习进度和最近学习时间。

归档继续使用现有更新接口；默认列表返回未归档知识库，并通过明确查询参数查看归档项。删除保持现有语义，但必须先验证所有权，再清理受控文件和向量集合。

### 标签

文档更新接口继续接受 `tags`。知识点更新接口增加 `tags`。两者都使用相同的规范化与边界验证，并在更新前验证所属知识库归当前用户所有。

## 前端范围

现有各功能页面、导航结构和视觉风格保持不变。截图中的“我的知识库”“选择知识库”等文案已经符合要求，无需重新设计。

只增加必要入口和字段：

- 现有解锁页扩展首次建号和用户名登录。
- 全局账号入口增加退出。
- 设置页现有“学习偏好”区域增加昵称和头像编辑，或在同一设置页增加紧邻的个人资料区块。
- 知识库现有创建/编辑弹窗增加领域、学习状态、目标和封面。
- 知识库卡片在不改变网格结构的情况下展示封面及已有统计。
- 文档和知识点现有编辑入口支持标签修改。
- 学习领域管理放在知识库创建/编辑流程或设置页内，不新增复杂导航层级。

新增内容必须复用现有 Ant Design 组件、间距、颜色和反馈方式。移动端行为保持现有断点规则。

## Alembic 迁移设计

### 迁移接管

新增标准 `alembic.ini`、异步 `env.py` 和 `versions/` 迁移链。数据库结构由 `alembic upgrade head` 管理，应用启动不再通过 `Base.metadata.create_all()` 和不断增长的 `run_compat_migrations()` 修改正式数据库结构。

Docker 和本地开发启动流程在 API 启动前执行升级。迁移失败时 API 不启动，并输出失败 revision。文档明确要求升级生产数据前备份数据库和上传目录。

### 基线与旧库接入

第一条 Alembic revision 表示迁移前的完整当前结构。全新数据库从该基线创建全部现有表，再执行账号基础 revision。已有数据库如果存在当前核心表但没有 `alembic_version`，由受控的迁移引导命令验证结构符合可接受的旧版本，登记基线后继续升级；不能仅凭“表存在”盲目 stamp。

引导过程必须：

1. 检查核心表、关键列和索引。
2. 对已知的现有兼容差异执行对应的前置修复或给出可操作错误。
3. 只在检查通过后 stamp 基线。
4. 运行后续 revision。
5. 再次执行时保持幂等，不重复回填数据。

### 账号与数据回填

账号迁移优先复用第一条 `user_profiles.id` 作为新用户 ID，并迁移昵称、密码哈希和时间字段。若旧库没有个人资料，则创建一个待首次设置的占位所有者；首次设置完成前不能访问私人业务接口。占位记录必须能被 setup 原子地完成，且不允许创建第二个账号。

迁移把所有旧知识库回填给该用户，并沿外键关系覆盖文档、知识点、卡片、学习活动、学习会话、目标、报告、测验和对话。回填不改变原业务记录 ID、原始文档路径、知识库 ID 或 Chroma 集合名。

旧 `workspaces.domain` 的非空名称按用户去重生成 `learning_domains`，再回填 `domain_id`。“未分类”和空值不生成领域记录，保持 `domain_id = NULL`。

### 兼容脚本退役

现有 `run_compat_migrations` 中仍有价值的结构变更和数据回填分别转换成明确 revision。Alembic 接管后，该函数不再在应用启动时执行结构 DDL。短期需要的运行时数据修复必须是显式、可审计的服务逻辑，不能继续充当无版本迁移系统。

### 降级策略

纯新增表和列提供常规 downgrade。涉及所有者回填、领域转换和唯一约束变化的 downgrade 以保留数据为优先，并在 revision 说明不可逆信息。迁移验证重点是可靠升级和备份恢复，不把破坏性降级作为正常发布流程。

## 数据流

### 首次设置与登录

1. 前端读取认证状态。
2. 没有已配置用户时显示首次建号；已有用户时显示登录。
3. setup 在单个事务中锁定/检查用户数量，完成用户、密码和偏好设置。
4. 登录验证用户名、有效状态和密码哈希，签发带 `sub` 和过期时间的令牌。
5. 后续请求由认证依赖加载用户；用户不存在、停用或令牌过期时返回 401。
6. 退出清除本地令牌并返回登录页。

### 私人数据访问

1. 路由获得 `current_user`。
2. 服务通过所有者范围查询目标知识库或直接带用户条件查询记录。
3. 子资源操作验证其所属知识库的 `owner_id`。
4. 查询不到范围内记录时返回 404。
5. 写入产生的新记录使用服务端当前用户 ID，不复制客户端用户标识。

### 封面上传

1. 路由先按当前用户加载知识库。
2. 文件服务验证大小、格式和文件头，使用随机文件名写入专用目录。
3. 数据库事务更新封面来源和相对路径。
4. 提交成功后删除被替换的旧本地文件；若事务失败，清理新临时文件。
5. 响应通过受控静态文件路由返回可展示 URL。

## 错误处理与并发

- 首次设置使用事务和唯一约束保证并发请求最多成功一个，其余返回 409。
- 用户名重复返回 409；登录失败统一返回“用户名或密码错误”，不暴露用户是否存在。
- 令牌缺失、无效、过期或用户停用返回 401。
- 跨用户资源访问返回 404。
- 删除仍被知识库使用的领域时，在一个事务中把对应知识库置为未分类后删除领域。
- 非法图片、超限图片和非法外部 URL 返回 422；磁盘写入失败不更新数据库。
- 封面数据库更新成功但旧文件清理失败时记录告警，并由后续孤儿文件维护任务处理，不回滚成功请求。
- 聚合统计中的空集合统一返回计数 0、进度 0 和空最近学习时间。
- Alembic revision 失败时停止启动，不尝试自动跳过或继续运行旧模型代码。

## 安全要求

- 使用常量时间密码验证，密码哈希参数保持当前强度或提高，不自行降级。
- `JWT_SECRET` 在启用账号后必须是非默认高熵值；启动时验证不安全默认值。
- 上传文件不使用原始文件名，不允许路径穿越，不把任意目录暴露为静态资源。
- 外部头像和封面只保存 URL，不由后端主动请求。
- 服务令牌使用常量时间比较并映射到明确用户。
- 日志不得记录密码、完整令牌、服务令牌或敏感个人偏好。
- 所有修改与删除接口在资源加载阶段执行所有权限制，不能在查询后仅依赖客户端判断。

## 测试策略

### 迁移测试

- 从全新空数据库执行 `alembic upgrade head`，验证所有表、外键、索引和唯一约束。
- 从代表当前版本的 SQLite 数据库升级，断言知识库、文档、对话、卡片、测验和活动的数量、ID、路径及关联不变。
- 验证 `UserProfile` 正确拆分为用户和学习偏好，密码仍可登录。
- 验证旧领域字符串去重转换且“未分类”保持空关联。
- 验证 owner/user 回填完整，不存在孤立私人记录。
- 对 PostgreSQL 方言验证迁移 SQL 和约束；项目 CI 条件允许时执行真实 PostgreSQL 升级。
- 重复运行升级命令，验证不会重复创建用户、领域或数据。

### 认证与隔离测试

- 首次设置成功、重复设置冲突、登录成功、错误凭据、当前用户和退出。
- 过期令牌、无效签名、已停用用户和不安全密钥启动校验。
- 在测试中直接创建两个用户，逐类验证知识库、文档、知识点、卡片、对话、活动、目标、测验和报告不能跨用户读取、更新或删除。
- 请求携带伪造 `user_id` 时，服务端忽略或拒绝该字段，实际归属始终是当前用户。
- 飞书服务令牌只访问绑定用户的数据。

### 知识库与领域测试

- 知识库创建、更新、归档、恢复和删除均受所有权约束。
- 同一用户 slug 唯一，不同用户允许相同 slug。
- 领域创建、重命名、同用户重名冲突、删除后知识库变为未分类。
- 文档数、知识点数、平均掌握进度和最近学习时间与底层记录一致。
- 手动学习状态和归档状态互不覆盖。

### 上传与标签测试

- 头像和封面上传、外部 URL、替换、清除、删除知识库后的文件清理。
- 非图片伪装、非法 MIME、超大文件、路径字符和非 HTTPS URL 被拒绝。
- 文档和知识点标签去空、去重、长度与数量边界。
- 人工标签在学习内容重新生成后仍保留，除非用户明确请求覆盖。

### 回归与前端验证

- 运行完整后端测试集。
- 运行完整前端 Node 测试集和 TypeScript/Vite 生产构建。
- 回归文档上传、解析、重新处理、混合检索和学习对话。
- 回归卡片、复习、练习、报告和学习活动。
- 使用绑定服务账号回归飞书问答。
- 手动检查现有桌面与移动端页面布局没有非必要变化；只出现已批准的新字段和账号入口。

## 验收映射

| 验收标准 | 验证证据 |
|---|---|
| 登录后只能看到自己的数据 | 双用户隔离 API 测试及所有权查询断言 |
| 可创建、编辑、归档和删除知识库 | 知识库 CRUD/归档集成测试与现有页面回归 |
| 可设置学习目标和所属领域 | Workspace 更新、领域 CRUD 和前端表单测试 |
| 支持用户自定义封面 | 上传、URL、替换、清理和权限测试 |
| 文档与知识点支持人工标签 | 标签规范化与重新生成保留测试 |
| 上传、检索和飞书问答仍可用 | 对应端到端回归测试 |
| 数据库升级后原有数据不丢失 | 旧库升级夹具的记录数、ID、路径和关联对比 |

## 实施边界与顺序

本规格按以下可独立验证的增量实施：

1. Alembic 基线、旧库引导和现有迁移逻辑接管。
2. User、LearningPreference、认证依赖与单账号登录流程。
3. 全部私人数据的所有权回填、服务端范围查询和飞书身份绑定。
4. LearningDomain 与 Workspace 扩展、统计响应和归档兼容。
5. 头像、知识库封面及受控文件服务。
6. 文档与知识点标签编辑和人工标签保护。
7. 在现有界面中增加必要字段与入口，并完成全量回归。

每个增量遵循测试先行。迁移和认证隔离通过前，不进入依赖其数据契约的界面改动；所有增量完成后执行完整升级演练、后端测试、前端测试、生产构建和关键流程验收。
