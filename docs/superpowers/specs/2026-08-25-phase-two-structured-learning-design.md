# 第二阶段：结构化学习内容与文档详情设计

## 背景与目标

现有系统已经具备文档上传、Celery 解析、向量检索、知识库详情页和基础知识点模型，但上传后的解析任务与学习内容生成没有形成可靠的自动链路。文档详情仍是原文件 iframe，引用只能查看检索片段，知识点管理也缺少前端闭环。

本阶段目标是在不替换现有 FastAPI、SQLAlchemy、Celery、ChromaDB 和 React 技术栈的前提下，完成以下闭环：

1. 文档上传请求快速返回，文档在事务提交后进入异步解析。
2. 解析成功后自动异步生成结构化学习内容。
3. 用户可查看文档章节、按页或章节阅读解析后的原文，并从回答引用定位到来源。
4. 用户可编辑、删除、合并和标记知识点，也可基于单个知识点生成卡片或练习。
5. 解析或生成失败时展示阶段、原因，并允许安全重试。

## 范围

### 本阶段包含

- 修复上传事务与 Celery 派发竞态。
- 将解析和 AI 学习内容生成拆成两个可重试、幂等的异步阶段。
- 扩展文档状态、标签和结构化学习内容字段。
- 在文档切片中保留页码、标题、标题层级、章节路径和文档 ID。
- 新增文档详情、章节原文、更新、重解析和重新生成接口。
- 新增知识点合并及单知识点练习接口。
- 完善知识库详情页和新增文档详情页。
- 让回答来源携带切片 ID，并支持跳转到精确来源。
- 为上述链路增加后端与前端自动化测试。

### 本阶段不包含

- OCR 服务；扫描版 PDF 会继续标记为无可提取文本并返回明确原因。
- Word、PPT、Excel 的浏览器原生排版还原；非 PDF 文件以解析后的结构化文本预览为主，原文件仍可下载。
- 多用户权限体系；继续遵循当前单用户知识库模型。
- 新任务队列或工作流引擎；继续使用 Celery 与 Redis。
- 新建通用任务表；任务进度保存在文档状态字段中，避免本阶段引入额外调度子系统。

## 总体架构

实现采用“扩展现有模型与管线”的方式：

```text
上传 API
  -> 保存文件与文档记录
  -> 提交数据库事务
  -> 派发解析任务
      -> 解析/切片/索引
      -> 标记 parsing=ready
      -> 派发学习内容生成任务
          -> 读取持久化切片
          -> LLM 生成结构化内容
          -> 更新文档与知识点
          -> 标记 learning=ready

回答来源
  -> document_id + chunk_id + page_num + heading
  -> 文档详情路由
  -> 加载对应切片并高亮
  -> PDF 使用 #page 定位，其他格式滚动到章节切片
```

解析与学习内容生成必须能够独立重试。重新解析会替换向量和关键词切片，成功后自动重新生成学习内容；仅重新生成学习内容不会重复解析文件。

## 状态模型

### 文档解析状态 `status`

- `pending`：文档记录已创建，尚未成功派发。
- `processing`：解析任务已派发或正在执行。
- `ready`：解析、切片和索引完成。
- `failed`：解析或任务派发失败，`error_message` 保存原因。

### 学习内容状态 `learning_status`

- `not_started`：尚未生成，也未排队。
- `queued`：生成任务已派发。
- `generating`：生成任务正在执行。
- `ready`：结构化内容与知识点生成完成。
- `failed`：生成失败，`learning_error_message` 保存原因。

状态更新必须在独立数据库事务中提交。重复任务通过“按文档替换生成内容”的方式保持幂等，不向现有内容追加重复知识点。

## 数据模型

### `documents` 扩展字段

- `tags: JSON`：用户维护的文档标签，默认空数组。
- `chapter_summaries: JSON`：章节标题、来源页码/路径和摘要数组。
- `core_concepts: JSON`：核心概念数组。
- `important_terms: JSON`：术语、解释和来源数组。
- `common_mistakes: JSON`：易错点数组。
- `prerequisites: JSON`：前置知识数组。
- `learning_order: JSON`：推荐学习步骤数组。
- `review_points: JSON`：用于复习的知识点摘要数组。
- `learning_error_message: TEXT`：学习内容生成失败原因。
- `processed_at: DateTime`：最近一次解析完成时间。
- `learning_generated_at: DateTime`：最近一次学习内容生成完成时间。

保留现有 `summary`、`outline` 和 `learning_status` 字段。`outline` 继续作为兼容字段存放换行分隔标题；新接口返回由切片推导的结构化章节目录。

### `document_chunks` 扩展字段

- `heading_level: Integer | null`：标题层级。
- `section_path: JSON`：从一级标题到当前标题的路径。

已有 `document_id`、`page_num`、`heading` 和 `chunk_index` 保持不变。向量存储的 metadata 同步写入相同字段。

### `knowledge_points`

现有字段覆盖标题、简述、详细解释、来源文档、来源页码/章节、重要度、难度、标签和掌握度。新增：

- `is_key: Boolean`：是否为用户重点。
- `mastery_status: String`：`not_started`、`learning`、`mastered`，默认 `not_started`。

`mastery` 浮点值继续用于进度计算；设置 `mastery_status=mastered` 时同步将 `mastery` 提升到 `1.0`，取消掌握时不自动清零已有学习记录。

### 兼容迁移

项目现有 SQLite 兼容迁移机制继续负责新增列。新安装由 SQLAlchemy `create_all` 创建完整结构；既有 SQLite 安装通过幂等 `ALTER TABLE` 添加字段。JSON 列在 SQLite 中使用 `JSON`/文本兼容默认值。

## 文档解析与切片

### PDF

- 每个 PDF 物理页使用一开始的真实页码。
- 读取目录层级并为每页继承最近一个有效目录标题，而不仅是目录项起始页。
- 保存目录层级和完整章节路径。
- 空白或扫描页保留页码元数据；整份文档无文本时解析任务失败并返回“需要 OCR”的明确原因。

### Word

- 按 Heading 1–9 标题样式分段。
- 使用标题栈生成 `section_path`，保留 `heading_level`。
- `page_num` 为空，避免把章节序号伪装成真实页码。
- 表格按原文顺序转成 Markdown 表格文本。

### PPT

- 每页幻灯片对应一个原始块，`page_num` 为幻灯片编号。
- 标题作为一级章节，备注与表格继续保留。

### Excel

- 每个工作表形成独立章节，工作表序号用于 `page_num`，工作表名用于标题。
- 预览内容保留表头和每行单元格值，以 Markdown 表格或稳定的列值文本表示。
- `section_path` 包含工作表名。

### 切片与索引

`TextSplitter` 继承原始块元数据，每个切片写入：

- `document_id`
- `workspace_id`
- `source_file`
- `chunk_index`
- `page_num`
- `heading`
- `heading_level`
- `section_path`

ChromaDB 与 `document_chunks` 使用同一稳定切片 ID：`{document_id}_chunk_{index}`。

## 异步任务设计

### 上传接口

文档文件和记录保存后，接口先把状态设为 `processing` 并显式提交事务，再调用任务派发器。这样 worker 无论多快启动都能读取文档记录，而且 API 不会在派发后用旧状态覆盖 worker 的更新。派发失败时状态改为 `failed`、记录“任务队列不可用”并再次提交，但绝不在上传请求中运行解析、嵌入或 AI 调用。

多文件上传逐个创建并提交，使每个文件拥有独立状态。单个文件派发失败不删除已保存文件，用户可从详情页重试。

### 解析任务

解析任务执行以下步骤：

1. 将解析状态设为 `processing` 并清空旧解析错误。
2. 解析文件并生成带结构元数据的块。
3. 分片、生成嵌入并原子替换 ChromaDB 文档向量。
4. 替换 `document_chunks` 中该文档的关键词索引切片。
5. 标记解析状态为 `ready`、学习状态为 `queued`，记录 `processed_at` 并提交事务。
6. 派发学习内容生成任务。

如果第 6 步派发失败，解析状态仍保持 `ready`，学习状态改为 `failed` 并记录队列错误，用户可单独重新生成。

### 学习内容生成服务与任务

从路由文件中抽出独立服务，输入为文档 ID，输出为经过校验的结构化学习内容。服务从 `document_chunks` 读取内容，不直接依赖 ChromaDB，以保证来源稳定且易测试。

模型 JSON 输出包含：

- `summary`
- `chapter_summaries`
- `core_concepts`
- `important_terms`
- `common_mistakes`
- `prerequisites`
- `learning_order`
- `review_points`
- `knowledge_points`

模型不可用或输出不合法时，任务失败并保留原因，不使用启发式内容伪装成 AI 结果。结构校验会限制数组长度、字符串长度、重要度和难度范围，并忽略未知字段。

生成成功时，在一个事务中删除该文档先前由生成流程创建的知识点并写入新知识点，然后更新文档结构化字段与生成时间。现阶段知识点没有“用户创建/AI 创建”字段，因此重新生成前由界面明确提示该文档现有知识点会被替换；不影响其他文档的知识点。

## 后端接口

### 文档接口

- `GET /documents/{id}`：返回完整文档状态、标签和结构化学习内容。
- `PATCH /documents/{id}`：编辑 `filename` 和 `tags`。
- `GET /documents/{id}/sections`：返回章节目录以及可分页的解析切片。
- `GET /documents/{id}/sections/{chunk_id}`：返回单个切片及前后相邻切片 ID。
- `POST /documents/{id}/reprocess`：清理错误并派发重新解析，返回 `202`。
- `POST /documents/{id}/regenerate-learning`：在解析已完成时派发重新生成，返回 `202`。
- `GET /documents/{id}/content`：继续提供原文件预览或下载。
- `GET /documents/{id}/status`：同时返回解析状态和学习内容状态及两类错误。

重解析与重新生成接口必须拒绝相同阶段已在运行的重复请求，并返回 `409`。

### 知识点接口

保留现有列表、创建、更新、删除和生成卡片接口，增加：

- `POST /learning/knowledge-points/merge`：接收 `target_id` 与至少一个 `source_id`。来源必须属于同一知识库；合并标签、解释和最高重要度后删除来源点。
- `POST /learning/knowledge-points/{id}/quiz`：为指定知识点创建一条练习题并返回。

更新接口允许修改 `is_key` 与 `mastery_status`。

### 知识库详情接口

`GET /learning/workspaces/{id}` 增加：

- 每个文档的解析与生成错误、标签和结构化内容。
- 从文档切片推导的章节目录。
- 最近 8 条该知识库学习活动。
- 最多 5 条继续学习推荐。

推荐规则保持确定性：优先解析失败或生成失败的文档，其次未整理的已解析文档，再其次高重要度且未掌握的知识点，最后推荐继续 AI 学习。

## 前端设计

### 知识库详情页

保留现有页头与三个页签，补充：

- 概览：基本信息、学习目标、进度、学习路线、最近学习记录和继续学习推荐。
- 知识点：展开查看、编辑、删除、重点/掌握切换、批量选择合并、生成卡片和单点练习。
- 文档：解析与生成双状态、失败原因、摘要、标签、进入详情、重解析和重新生成操作。

页面加载使用一次详情请求；执行操作后只刷新详情，不启动多个重复轮询。存在处理中状态时使用单个定时器刷新。

### 文档详情页

新增路由 `/knowledge/:workspaceId/documents/:documentId`，布局包括：

- 文档头部：名称、标签、解析状态、学习生成状态和操作按钮。
- 左侧章节目录：按 `section_path` 与标题层级展示。
- 中部原文：PDF 显示原文件并通过 `#page=N` 定位；Word、PPT、Excel 和文本文件显示解析切片。
- 右侧学习内容：摘要、章节摘要、核心概念、术语、易错点、前置知识、学习顺序和复习点。

移动端将目录和学习内容放入抽屉，原文保持主区域。

### 引用定位

后端回答来源增加 `chunk_id`。前端来源按钮和正文中的 `[资料N]` 引用都调用同一个 `openSource` 行为：

1. 若来源有 `document_id` 和 `chunk_id`，导航到文档详情并传递 `chunk`、`page` 查询参数。
2. 文档详情加载后选中并滚动到目标切片。
3. PDF 同时将 iframe 地址更新为 `#page={page_num}`。
4. 缺少文档 ID 的历史引用继续使用证据抽屉降级展示。

正文引用通过纯文本预处理转换为内部引用链接；代码块和行内代码中的相同文本不得转换。

## 错误处理

- 队列派发失败：快速返回，记录阶段错误，提供重试按钮。
- 文件解析失败：保留原始文件，展示解析器错误；重新解析覆盖旧错误。
- 扫描 PDF：提示需要 OCR，不进入 AI 生成。
- AI 配置缺失、超时或 JSON 不合法：学习状态失败，解析结果仍可浏览和检索。
- 重复操作：运行中返回 `409`，前端提示任务已在进行。
- 删除文档：删除文件、向量、关键词切片、该文档知识点和结构化内容。
- 合并知识点：跨知识库请求返回 `400`，不存在的知识点返回 `404`。

## 测试策略

### 后端

- 上传在任务派发前已提交，worker 能查到文档。
- Broker 不可用时不会调用同步解析。
- 解析成功后派发学习生成任务；派发失败只影响学习状态。
- 重新解析和重新生成的状态冲突、成功派发及失败错误。
- 学习生成 JSON 校验、幂等替换和失败保留。
- PDF 页码与目录继承、Word 层级路径、PPT 页码、Excel 工作表结构。
- 文档章节列表与单切片定位。
- 知识点编辑、删除、合并、重点/掌握和单点练习。
- 来源响应包含 `document_id`、`chunk_id`、章节和页码。

### 前端

- 知识库详情渲染双状态、最近记录和推荐。
- 文档详情按查询参数选择切片和 PDF 页码。
- 引用文本转换不会破坏代码块，并能触发来源导航。
- 知识点编辑、删除、合并、状态切换、卡片和练习操作。
- 失败原因展示和重试按钮。
- 生产构建通过。

所有新增行为遵循测试先行：先运行目标测试并确认因功能缺失而失败，再实现最小代码使其通过，最后运行完整回归套件。

## 验收映射

| 验收项 | 对应设计 |
|---|---|
| 上传后自动生成摘要和知识点 | 解析任务成功后自动派发学习内容生成任务 |
| 详情页展示结构化学习内容 | 知识库详情扩展与文档详情学习内容区域 |
| AI 任务不阻塞上传 | 上传提交后只派发 Celery，禁止同步回退 |
| 用户编辑和删除 AI 内容 | 知识点完整管理、文档字段编辑与重新生成提示 |
| 点击引用查看对应原文 | `chunk_id` 来源、文档详情路由和页码/切片定位 |
| 解析失败查看原因并重新处理 | 双状态错误字段、失败展示与重解析接口 |

## 发布与兼容

- 先部署数据库兼容迁移与后端，再部署 Celery worker，最后部署前端。
- 新后端对旧前端保持兼容：现有字段和接口不删除。
- 新前端对历史来源缺少 `chunk_id` 的记录使用证据抽屉降级。
- 已解析旧文档不会自动补生成；详情页将其显示为 `not_started`，用户可点击重新生成。新上传文档走完整自动链路。
